# Resuming a session

Run to its end before any other work, after a pause, a kill, a usage stop or any gap. What you resume from is what a command proves now: the branch, the state and a report on disk.

1. **The state.** Run `orchestra status`. Where it finds no session on this branch, this is no resume: say so and wait for a starter. Then run `orchestra note resuming`, the first write: until this Claude Code session holds the state, its hooks keep no message and check no turn's end. Where that is refused naming another Claude Code session, as after `/clear`, follow the refusal to `orchestra mode takeover "<reason>"`. Where the takeover is refused until a time, as after a crash, tell the owner that time, run `orchestra mode takeover "<reason>" --wait` in the background, and meanwhile do steps 2, 5 and 6, which write nothing. It retries for 15 minutes; where it exits 2, tell the owner the session its refusal names, which still writes, and the time a takeover succeeds.
2. **The branch.** State the branch, its last commit subjects and whether `git status --porcelain` prints anything, each from its command. A change in your checkout that you cannot attribute to a landing is a question for the owner before you touch it.
3. **Each agent**, by the status the output gives it.
   - *Reported and not judged*: judge it now; its report lost nothing.
   - *Running*: leave it, and note what it owns. One the output marks suspect because its transcript fell silent is treated as stopped: its rows route and its successor's brief passes with no takeover. One whose transcript is not found reads as live until it is discarded: take the not-resumable path.
   - *Stopped*: resume it with `SendMessage` to its name, telling it to continue from its report and its last commit. Where the name no longer resolves, its record in the state's `agents` folder holds its id. Resume the critical path first. One whose reason reads `took this state over`, one stopped before a takeover the log names, or a driver, whose worktree went at its stop, cannot be resumed: take the next path.
   - *Not resumable, or its resume refused*: clear the old agent away first, since a successor's brief is refused while that agent's unlanded work changes its files or holds its rows. Where its report reads `DONE` or `DONE-WITH-CONCERNS`, judge it first, since `land` and `prune` keep an agent whose report waits. `orchestra land NAME --preview` shows what its branch and worktree hold. Judge each uncommitted edit as work or as a plant left behind, and save the work and a patch of its commits to the state's `scratch` folder, since the discard below keeps neither. Land the branch where its worktree holds nothing uncommitted and the report carries the evidence for every commit. Take back each row it holds with `orchestra route ending <NAME>-F1`, then remove an unlanded agent's worktree and branch with `orchestra prune --discard NAME`; a row `route` refuses for a live agent routes once that settles it. Where `prune` keeps a crashed agent's tree as mid-turn, run it again at the time it names rather than removing the tree by hand, since until then it cannot tell a dead agent from one still writing. Brief the successor from the old brief, its messages file, its report and what you saved, passed as claims.
4. **The harness.** Background commands are gone: start `orchestra ci --wait` again where a run is open. `orchestra doctor` says whether what the project needs still answers after a restart.
5. **The mode.** Where the status opens with an `away` line, the away mode holds until the owner's word ends it, even past the time it names.
6. **The orders.** Read `PLAN.md`, the owner's words under `## The request` first, the rulings (`rulings.jsonl` beside the state's folder) and the open questions (`orchestra ask`) again, and say which the work in flight touches.
7. **The next action.** Rewrite `NOW.md`, state the single next action and why, and continue, in parallel where that shortens the critical path.

At a stop, message no agent to save its work: its commits are on its branch and its findings are in its report.

Redo what cannot be shown complete, derive again nothing a command answers, and audit again no work whose evidence still holds.
