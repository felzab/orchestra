# The review

Capture once the session's files have stopped moving. How widely to read is your judgement, made from what changed and what a defect there could break, and the steps say where to add a reading or decline one. Record each such choice, `orchestra note "Review: <what was added or declined>, <what changed>, <what a defect could break>"`, and weigh each reading against the weekly `usage` row of `orchestra status --measure` and the points per agent the latest estimate gives, since every reading is paid from it: where one would not fit, ask the owner.

1. **Capture.** `orchestra diff --tree` captures the change and its commit messages, checks the tip out as a tree that stays put, so every agent judges the same state, and prints the lenses due.
2. **The lens round.** Give each lens printed due or undeclared, except `use`, which step 7 runs, an agent of the type the lens names, or a note `orchestra note "Lens declined: <name>, <reason>"`, which `orchestra status --end` checks. A type this session cannot dispatch gets that note too, since no other type can answer its question. Over a large change each lens gets an agent of its own, since a reader carrying several checklists goes shallow on each; lenses of one `**Run by.**` type may share an agent, named together on its `Lens:` line, where their span is small enough for one reader to hold every checklist. Besides the lenses, a change that cuts across the tree, such as a rename, a moved signature or a rule repeated in many files, gets an agent of its own over exactly its commits, since each lens reader sees a fragment of it; so does the part whose defect would break most, such as stored data or a rule every agent loads. Each has seen none of the work and gets the paths the capture printed; `conformance`'s also gets the state's `PLAN.md`, `findings.jsonl`, whose rows `orchestra show <row>` prints whole, and `../rulings.jsonl`. Draft these briefs while the last writers run, then fill in the paths and lenses the capture prints.
3. **Judge** each report as [SKILL.md](SKILL.md) says, and route what a fixer would take to the queue `ending` (`F2=route:ending`), since every finding takes a disposition. A `conformance` finding on what a person still does by hand goes to the queue `owner`: what to build is the owner's choice.
4. **Cluster by cause** before any fix. Rows that share a cause get one repair, designed once at that cause; a patch per row leaves the cause in place. Write each cluster's slice into `PLAN.md` before any brief, so `orchestra status --measure` lists the fix work.
5. **Verify each row a fixer would take, and each `defect` row you would close `NOT A DEFECT` or `MOOT`, held on `ending` until its verdict.** Group those rows by file area and give each group to one verifier, its rows named in its `WORK`, because a verifier per row rebuilds the context each time, and send each as soon as its area's reports are judged, since a verdict needs no other row; brief a cluster's fix once no reader still out could share its cause. Judging its report closes each `REFUTED` row by the verdict and takes a disposition for every other, as in `orchestra judge VERIFY-1 REVIEW-F3=route:ending --verdict "<one line>"`, which leaves the row on the queue. A `NOT JUDGED` row's command goes to a driver.
6. **One fix round.** Brief one writer for each cluster that stands, with its rows on `Rows:` and a `CORRECTED` row as its verdict corrects it.
7. **Use.** Once the fixes land, a driver with `Lens: use` takes a fresh `orchestra diff --tree`, so a newcomer meets what ships; its brief carries each drive of the change already run, with its transcript's path and result, and it repeats one only where the fixes changed what that drove. Where no driver can be dispatched, `use` gets step 2's note. A writer fixes each defect it finds, and that fix gets a step-8 reading of its own once landed. Where the change is a rule or page meant to change what agents do, give one small task it bears on to two researchers, the text before the change (`git show <base>:<path>`) pasted into one brief and the text after into the other; alike answers, a change that changes nothing, go to the owner with `orchestra ask`. A file an agent loads by itself, such as a project's CLAUDE.md, a rules file or its own definition, reaches both alike once landed, so it takes this test while you judge its writer's report, before `land`; both still load the old text, so the after brief says its pasted text replaces that file, and alike answers to a change that only narrows a rule are no finding.
8. **Reading the fixes.** As step 7's driver goes out, read the fixes again where they changed what a defect could break silently, and not where a test seen red then green and CI hold them alone: a fresh `orchestra diff --tree` and the files each fix changed go to fresh agents as in step 2, dedicated readers included, for the due lenses whose `Silent.` line says yes, except `use`, and one agent may hold several lenses, since a reading of fixes spans little. A test holds only the row it was written for, and a step-2 reading the first round missed goes out before this step. A defect found is fixed at its own lines by a new writer, or by you where you can spell it out, since `land` removed the fix's writer. A further round follows while a reading finds defects in what the last fixes wrote, and stops when one finds none that matter, since each round finds less and costs a wave. A finding on inputs the request never named goes to the queue `owner` as outside the request, not to a fix.

The gate of this phase is `orchestra findings` exiting 0.
