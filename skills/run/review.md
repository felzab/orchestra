# The review

Run once the session's files have stopped moving. The cycle is the steps below, once each, and it ends on a fix. Reading any text a third time runs only on the owner's word, because each round finds less and costs a wave.

1. **Capture.** `orchestra diff --tree` captures the change and its commit messages, checks the tip out as a tree that stays put, so every agent judges the same state, and prints the lenses due.
2. **One lens round.** Give each lens printed due or undeclared, except `use`, which step 7 runs, an agent of its own, of the type the lens names, since a reader carrying several checklists goes shallow on each; or a note `orchestra note "Lens declined: <name>, <reason>"`, which `orchestra status --end` checks. A type this session cannot dispatch gets that note too, since no other type can answer its question. Each has seen none of the work and gets the paths the capture printed; `conformance`'s also gets the state's `PLAN.md`, `findings.jsonl` and `../rulings.jsonl`.
3. **Judge** each report as [SKILL.md](SKILL.md) says, and route what a fixer would take to the queue `ending` (`F2=route:ending`), since every finding takes a disposition. A `conformance` finding on what a person still does by hand goes to the queue `owner`: what to build is the owner's choice.
4. **Cluster by cause** before any fix. Rows that share a cause get one repair, designed once at that cause; a patch per row leaves the cause in place. Write each cluster's slice into `PLAN.md` before any brief, so `orchestra status --measure` lists the fix work.
5. **Verify only what a fixer would take.** Group those rows by file area and give each group to one verifier, its rows named in its `WORK`, because a verifier per row rebuilds the context each time. Judging its report closes each `REFUTED` row by the verdict and takes a disposition for every other, as in `orchestra judge VERIFY-1 REVIEW-F3=route:ending --verdict "<one line>"`, which leaves the row on the queue. A `NOT JUDGED` row's command goes to a driver.
6. **One fix round.** Brief one writer for each cluster that stands, with its rows on `Rows:` and a `CORRECTED` row as its verdict corrects it. Its dispatch routes the rows to it, and its landing closes each one a commit names fixed.
7. **Use.** Once the fixes land, a driver with `Lens: use` takes a fresh `orchestra diff --tree`, so a newcomer meets what ships; where no driver can be dispatched, `use` gets step 2's note. A writer fixes each defect it finds before step 8, which reads that fix too.
8. **One reading of the fixes.** A fresh `orchestra diff --tree` and the files each fix changed go to fresh agents, one a lens as in step 2, for every due lens whose `Silent.` line says yes, except `use`. A defect found goes back to that fix's writer, at the defect's own lines, and that fix is read again only on the owner's word, since each fix is new text another reading finds edges in. A finding on inputs the request never named goes to the queue `owner` as outside the request, not to a fix.

The gate of this phase is `orchestra findings` exiting 0.
