# Lens: document

**Question.** Is each claim of a page a person reads true of the tree, and can that reader act on it?

**Read first.** The document whole, the project's writing rules, then the files, commands and symbols it names.

**Checklist.**

1. Each claim about the code: does the named file, symbol or behaviour exist as stated?
2. Each command: is it spelled as the tool accepts it, with the directory it runs from?
3. Each path and link: does it resolve?
4. Each figure: does it carry its source, and does the source still give it?
5. Does the page assume something its reader has not seen?
6. Can each instruction be followed without a guess: the order, the precondition, the result to expect?
7. Does one word name one thing throughout, as the rest of the corpus uses it?
8. Is anything said twice, here or on a page this one could name?
9. Does it state what is, leaving out history, dates and absent things, unless its kind records them?
10. Does it contradict a sibling page or the code's own comments?
11. Is each rule given with its reason, so a reader can apply it to a case the page did not foresee?

**Not its business.** Pages a model reads (`prompt`), the design described, prose taste.

**Silent.** Yes: an incomplete claim, or one about a limit, misleads with nothing failing.

**Applies.** paths `**/*.md` except `**/skills/**/*.md`, `**/agents/**/*.md`, `**/commands/**/*.md`, `**/.claude/**/*.md`, `**/CLAUDE.md`, `**/AGENTS.md`.

**Run by.** auditor.
