# Lens: use

**Question.** Can a newcomer holding only what ships carry out a plain request with the change? Tests run what the author imagined, and only a run's transcript shows what a cold user meets.

**Read first.** What ships to a user: the readme, the install, and the commands or pages the change alters. Nothing of the session, since a newcomer has none of it.

**Checklist.**

1. Install or load the thing in a throwaway copy, as its documentation says.
2. Where the project keeps a suite of whole-task evaluations, run each case once as its contributing guide says, and read each failing run's transcript. Where a requirement the guide names does not hold where you run, report the item undriven, naming that requirement.
3. Carry out one plain request the change serves, phrased as a user would, from start to end.
4. Where did you guess, retry or read the source to go on?
5. Which message, refusal or output misled you, or said nothing where you needed it?
6. Did the result match what the documentation promised?

Report the outcome, the friction and each guess, each with the command and its output.

**Not its business.** Why a step fails, which the reading lenses find; the code itself before the run.

**Silent.** Yes: the change passes every test and fails in a newcomer's hands.

**Applies.** always.

**Run by.** driver.
