# Lens: disclosure

**Question.** Does anything the change publishes name a person, a machine, a private project or a credential? A public push cannot be taken back, and a commit message is changed only by rewriting history.

**Read first.** The project's statement of what it publishes, where it keeps one; with none, list each name the change publishes in the report, for the coordinator to put to the owner. Then each commit's change, `git log -p --cc <from>..<to>`, since a push publishes every commit, not only the net diff: at a push's gate after the first push, from `@{upstream}` to your brief's `Base:` commit alone, each earlier push read at its own; otherwise over the span the capture's file name holds, beside its diff and commit messages.

**Checklist.**

1. A path of one machine: a home folder, a user name, a drive letter.
2. A private project's, repository's or tool's name, or a link to one.
3. A real person's name, address or identifier, in a fixture, an example or a log.
4. Another person's words, quoted without their leave.
5. A credential, token, key or internal host name, a revoked one included.
6. A private register's rulings, reviewers, process or row ids, named in a commit message; the subject `Merge <NAME> into <branch>` that `orchestra land NAME` writes is the plugin's form, and no hit.

Name each hit by file and line, or by commit and line.

**Not its business.** A secret reaching a log or a response at run time (`security`).

**Silent.** Yes: nothing fails, and the disclosure is permanent once pushed.

**Applies.** declared.

**Run by.** researcher.
