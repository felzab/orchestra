# Lens: conformance

**Question.** Does the tree hold every ruling and plan item, is every closed row closed in fact, and what does the change still leave the owner to do by hand? A dropped requirement fails no check, so it is compared with the written standard, as an inspection does.

**Read first.** What the brief names: the owner's request in the owner's words, the rulings, the plan's slices and the closed rows with their commits; then the frozen tree.

**Checklist.**

1. Each sentence of the request and each ruling: which line of the tree meets it, and which has none?
2. Each ticked slice: does a landed commit hold every file it names?
3. Each row closed as fixed: does its commit change what the finding named, at its lines?
4. Each row closed as no defect: does its reason hold of the tree?
5. What did the change do that no request or ruling asked for?
6. Which goal is met only when a person remembers to trigger it?
7. Walking the owner's path from start to end, which step do they still do, remember or retype each time?
8. What does the change assume its user knows that nothing tells them?

For items 6 to 8 propose no fix: name what the person does by hand and how often, since what to build is the owner's choice.

**Not its business.** Whether what was asked is right, whether what meets it is correct (every other lens).

**Silent.** Yes: an unmet item or a false closure passes every check.

**Applies.** always.

**Run by.** researcher.
